# Sorisketch 설계 문서

> 완성 기준: 이용자가 새로운 이야기를 즐기는 동안 **실제로 판소리의 소리를 듣고, 그 표현을 이해하며, 소리판에 참여했다고 느끼는 것.**

## 1. 전체 화면 구성

| 순서 | 화면 | 내용 |
|---|---|---|
| 1 | 시작 | 서비스 소개, "소리판 열기"(이 클릭으로 오디오를 깨움), 이용 방법 3단계, 소개·발표 모드 링크 |
| 2 | 작품 선택 | 다섯 바탕 카드: 대표 그림, 한 줄 소개, 주요 인물 |
| 3 | 배경 설정 | 원작 배경 유지 / 현대 대학 캠퍼스 / 회사 / 미래 도시 / 직접 입력(AI 모드) |
| 4 | 도입 | **원작 이야기**(원작 표시), 「판소리」 해설 카드, **추임새 연습**(중중모리 장단 원을 보며 맺히는 자리에 넣기), 진행 방법 |
| 5 | 이야기 진행 | 무대(그림) + 아래 패널: 아니리 → 창 → 해설 카드 → 선택(3개 + 직접 입력) |
| 6 | 결말·체험 결과 | 결말, 원작과 달라진 점(나란히 비교), 나의 선택, 들은 장단 다시 듣기, 추임새 성적, 해설 카드 다시 보기, 원작/창작 구분 안내 |
| 7 | 이 소리판에 대하여 | 기획 의도, 국악 요소, 원작·창작 구분, 소리·그림 제작 방식, AI 활용 범위, 참고 자료 |
| 8 | 발표 모드 `?present` | 큰 QR(같은 Wi-Fi 주소 자동), 접속 안내, 대표 장면 시연(수궁가 각본) |

공통: 상단 바(처음으로, 모드 표시, 음소거, 설정 — 음량·아니리 음성 읽기·글자 크게·추임새 안내). 휴대폰에서는 무대가 위에 붙어 있고 패널만 넘어갑니다.

## 2. 데이터 구조

**장면(scene)** — AI 응답과 각본이 같은 모양을 쓰고, `public/js/story/schema.js`의 `normalizeScene()`이 서버·브라우저 양쪽에서 검증합니다. 카탈로그에 없는 id는 기본값으로 바뀝니다.

```js
{
  title, summary,                       // summary는 다음 요청의 이야기 이력으로 쓰임
  stage: { background, tint, costume, characters: [{ id, name, expression, position }], props, effect },
  aniri: [{ speaker, text }],           // speaker: 'narrator' | 등장인물 id
  chang: { lines, jangdan, jo, singer, why } | null,
  compareJangdan,                       // 비교 감상용 다른 장단
  learn: { type: 'element'|'passage'|'jangdan'|'jo', id } | null,
  choices: [{ label, hint }],           // 결말이 아니면 3개
  ledger: { relationships, items, unresolved, facts },
  ending: { title, summary, changes } | null,
}
```

**카탈로그** — `public/js/data/works.js`(작품·인물·배경·소품·효과·표정), `public/js/data/gugak.js`(장단·조·판소리 요소·원작 대목). AI는 이 id 안에서만 고를 수 있습니다.

## 3. AI 이야기 생성과 선택 이력 관리

- 서버(`lib/story.js`)가 OpenAI(Responses API, 엄격 모드 JSON 스키마) 또는 Claude(구조화 출력)를 같은 프롬프트·같은 스키마로 호출합니다. `AI_PROVIDER`로 고르거나, 있는 키로 자동 선택합니다. 시스템 프롬프트(작성 원칙 + 전체 카탈로그)는 모든 요청에서 같아 캐시에 유리합니다.
- 브라우저의 `Director`가 상태를 들고 매 요청에 함께 보냅니다(서버는 무상태).
  - `history`: 장면별 제목·요약·사용자의 선택·쓰인 장단 (최근 8개)
  - `ledger`: 인물 관계, 가진 물건·정보, 미해결 문제, 확정된 사실 → AI가 갱신한 전체 목록을 돌려줌
  - `shownCards`: 이미 보여 준 해설 카드(반복 방지)
  - `sceneIndex / totalScenes`: 기본 5장면. 마지막 장면은 반드시 결말(원작과 달라진 점 포함)
- 프롬프트 규칙: 말투만 다른 선택지 금지, 선택은 행동·관계·결과·얻고 잃는 것 중 하나 이상을 바꿈, 직전 선택 반영, 비슷한 사건 반복 금지, 장단은 감정이 아니라 장면의 극적 속도로 고름, 국악 사실은 카탈로그 범위 안에서만.
- 직접 입력 행동(80자 제한)은 세계·인물 상황에 맞게 해석, 부적절한 입력은 이야기 안에서 돌림.
- 안정성: 응답 실패 시 "다시 시도" 또는 "각본으로 이어 가기", IP별 요청 제한, 70초 시간 제한, 거절(refusal) 시 서버 측 대체 모델(`fallbacks: "default"`) 사용.

## 4. 음악·음성 구현 — 현실적인 방안과 검증할 부분

| 구분 | 현재 구현 | 표시 |
|---|---|---|
| 실제 전통 판소리 감상 | 원작 대목 카드(맥락·장단). 음원 자리는 비어 있음 | 「원작 감상」 |
| 장단 | 실제 소리북 녹음 한 바퀴를 끊김 없이 반복, 장단 원 시각화. 합성 북은 예비용 | 「고수의 소리북 녹음」 |
| 창 장면 | 장면의 장단과 같은 장단의 **실제 판소리 녹음**(같은 작품 우선). 악구가 바뀌는 시각(`cues.json`)을 추임새 자리로 사용. 새 사설은 자막으로 표시하고, 실제 소리북 위에 얹어 장단에 맞춰 흘려 볼 수 있음 | 「실제 판소리 — 원작 사설로 부른 녹음」, 새 사설은 「창작」 |
| 아니리·해설 대사 | 자막(타자 효과) + 선택 시 기기 음성 합성 | 설정에 「일반 음성 합성」 표기 |

**먼저 검증할 것**
1. 실제 녹음(원작 사설) + 새 사설 자막 방식이 장면과 충분히 이어지는가, 아니면 새 사설을 직접 녹음한 짧은 창이 필요한가 → 대표 장면 1개로 비교 청취
2. 휴대폰(특히 iOS 무음 스위치·저전력 모드)에서의 재생 안정성과 추임새 타이밍 판정 정확도
3. AI 생성 대기 시간(현재 대기 중 국악 상식 카드 표시)이 몰입을 얼마나 끊는가 — `CLAUDE_EFFORT`, 모델 선택으로 조정
4. 새 사설을 실시간 판소리 가창으로 생성하는 기능은 품질 검증 전까지 핵심 기능으로 두지 않음(확장 목표)

## 5. 그림 제작과 장면 구성

- 화풍: 한지 질감(노이즈 필터) + 먹선 + 절제된 오방색의 민화풍. 휴대폰에서도 표정이 보이도록 머리가 큰 인물.
- 조합 방식: **배경 16종 × 시간대 5종 × 인물 23명(표정 8종, 의상 전통/현대/미래) × 소품 15종 × 효과 10종**을 SVG로 실시간 조합 → 새 배경·자유 전개에도 화풍과 인물 외형이 유지되고 대기 시간이 없음.
- 음악 연결 연출: 아니리에서는 말하는 인물 강조, 창이 시작되면 노래하는 인물 쪽으로 천천히 확대하고 장단 빠르기에 맞춰 몸짓 속도 변화, 북의 "덩·쿵"에 맞춰 무대가 살짝 들썩, 추임새는 붓글씨로 튀어나오고 인물이 고개를 끄덕임.
- AI 이미지 생성은 확장 검토: 장면마다 생성하면 인물 일관성과 대기 시간이 문제 → 결말 장면 1장만 생성하는 방식 등을 시험해 볼 수 있음.

## 6. 첫 시제품의 범위와 개발 순서

1. ✅ 데이터 카탈로그(작품·인물·장단·대목) 정의
2. ✅ 장면 스키마와 검증, 각본 6편(수궁가 원작·회사, 흥보가 원작·캠퍼스, 춘향가·심청가·적벽가 원작) — AI 없이 다섯 바탕 모두 끝까지 체험 가능
3. ✅ 소리 엔진(실제 녹음·소리북 장단 재생, 추임새 판정), 장단 원
4. ✅ 민화풍 인물·배경·무대 연출
5. ✅ AI 장면 생성(OpenAI 또는 Claude 구조화 출력) + 실패 시 각본 전환
6. ✅ 결과 화면, 소개·출처, 발표 모드
7. ✅ 실제 OpenAI 키(gpt-5.5)로 AI 모드 5장면 끝까지 시험 (장면당 약 15초)
8. ⬜ 국악 정보 원전 재확인(`verify: true` 항목), 원작 음원·직접 녹음 자산 넣기
9. ⬜ 휴대폰 실기기 시험(iOS/Android), 발표장 Wi-Fi 시험, 배포
10. ⬜ 확장: 관객 투표로 함께 진행하는 발표 모드, 장면별 AI 삽화, 녹음한 창작 후렴

## 7. 평가 기준 대응

| 항목 | 이 작품에서 보여 줄 근거 |
|---|---|
| 국악에 대한 이해 (30%) | 창/아니리 구분 진행, 6가지 장단의 박 구조·빠르기 체험과 비교 감상, 조와 시김새, 추임새의 자리, 원작 대목의 맥락 |
| 기획의 창의성 (30%) | 원작에서 출발해 배경까지 바꾸는 평행세계, 선택이 사건·관계·결말을 바꾸는 AI 이야기, 그림·소리·추임새가 결합된 소리판 |
| 구현 및 완성도 (30%) | 설치·가입 없는 모바일 접속, AI 실패 시에도 끝까지 진행, 장면 조합형 그림, 접근성(글자 크게, 음성 읽기, 동작 줄이기 대응) |
| 과정 설명 및 발표 (10%) | 원작/창작/AI 해석의 구분, AI 활용 범위 공개, 발표 모드 QR과 대표 장면 시연 |
